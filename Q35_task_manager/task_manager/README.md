### UNIT VI — Node.js (Primary Unit)

#### What is Node.js?
Node.js is a **JavaScript runtime** — it lets you run JavaScript code on the **server side** (outside the browser). Built on Chrome's V8 JavaScript engine.

Key characteristics:
- **Single-threaded** — one thread handles everything
- **Non-blocking I/O** — doesn't wait for operations (file, DB, network) to complete; moves on and comes back when ready
- **Event-driven** — uses an Event Loop to handle thousands of concurrent requests
- **NPM** — Node Package Manager, 1.8 million+ packages

#### Express.js
Express is a **minimal, flexible web framework** for Node.js. Without it:
```javascript
// Raw Node.js (messy):
const http = require('http');
http.createServer((req, res) => {
  if (req.url === '/api/tasks' && req.method === 'GET') { ... }
  else if (req.url === '/api/tasks' && req.method === 'POST') { ... }
  // ...hundreds of lines of if-else
}).listen(3000);

// With Express (clean):
app.get('/api/tasks', handler);
app.post('/api/tasks', handler);
```

#### Routing in Express
```javascript
// Route = HTTP method + URL path + handler function
app.get   ('/api/tasks',     (req, res) => { ... }); // Read
app.post  ('/api/tasks',     (req, res) => { ... }); // Create
app.patch ('/api/tasks/:id', (req, res) => { ... }); // Update
app.delete('/api/tasks/:id', (req, res) => { ... }); // Delete
```

#### REST API (REpresentational State Transfer)
A design style for web APIs using HTTP:

| HTTP Method | CRUD   | Our Route              | Task |
|-------------|--------|------------------------|------|
| GET         | Read   | GET /api/tasks         | Task 2 |
| POST        | Create | POST /api/tasks        | Task 1 |
| PATCH       | Update | PATCH /api/tasks/:id   | Task 3 |
| DELETE      | Delete | DELETE /api/tasks/:id  | Task 4 |

#### HTTP Status Codes
```
200 OK           — success (GET, PATCH, DELETE)
201 Created      — new resource created (POST)
400 Bad Request  — client sent invalid data (validation failed)
404 Not Found    — requested resource doesn't exist
500 Server Error — unexpected server crash
```

#### Middleware
Functions that run between receiving a request and sending a response:
```
Request → [cors()] → [express.json()] → [logger] → [Route Handler] → Response
```
```javascript
app.use(cors());                          // middleware 1: CORS headers
app.use(express.json());                  // middleware 2: parse JSON body
app.use(express.static('public'));        // middleware 3: serve HTML/CSS files

// Custom middleware:
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next();                                 // MUST call next() or request hangs!
});
```

#### URL Parameters vs Query Strings
```javascript
// URL Parameter (:id) — part of the path
// /api/tasks/abc-123 → req.params.id = "abc-123"
app.get('/api/tasks/:id', (req, res) => {
  const id = req.params.id;
});

// Query String (?key=value) — after the ? in URL
// /api/tasks?status=pending → req.query.status = "pending"
app.get('/api/tasks', (req, res) => {
  const status = req.query.status;
});

// Request Body — sent in POST/PATCH body
// Requires: app.use(express.json())
app.post('/api/tasks', (req, res) => {
  const { title, priority } = req.body;
});
```

#### JSON (JavaScript Object Notation)
```javascript
// res.json() — sends JSON response
// Automatically sets Content-Type: application/json header
res.json({ success: true, tasks: [...] });

// JSON.stringify() — JS object → JSON string
const str = JSON.stringify({ name: "Task", done: false });
// → '{"name":"Task","done":false}'

// JSON.parse() — JSON string → JS object
const obj = JSON.parse('{"name":"Task"}');
// → { name: "Task" }
```

#### In-Memory Storage
Our app stores tasks in a JavaScript array:
```javascript
let tasks = [
  { id: "abc", title: "Buy groceries", status: "pending" },
  { id: "def", title: "Study React",   status: "completed" }
];
```
- Data is LOST when server restarts
- Fine for lab demo; production apps use MongoDB, MySQL, etc.

### UNIT II — JavaScript Array Methods (used in server.js)

```javascript
// find() — returns first matching element (or undefined)
const task = tasks.find(t => t.id === id);

// findIndex() — returns INDEX of first match (or -1)
const index = tasks.findIndex(t => t.id === id);

// filter() — returns NEW array with elements that pass test
const pending = tasks.filter(t => t.status === 'pending');

// map() — transforms each element, returns new array
const titles = tasks.map(t => t.title);

// push() — adds element to END of array (mutates original)
tasks.push(newTask);

// splice(index, deleteCount) — removes elements (mutates)
tasks.splice(index, 1); // remove 1 element at index

// reduce() — builds single value from array
const byCategory = tasks.reduce((acc, t) => {
  acc[t.category] = (acc[t.category] || 0) + 1;
  return acc;
}, {});
```

#### Spread Operator (...)
```javascript
// Copy array:
let filtered = [...tasks]; // creates shallow copy (won't mutate original)

// Merge objects (used in PATCH to update only given fields):
tasks[index] = {
  ...tasks[index],    // keep all existing fields
  status: 'completed', // override this one
  updatedAt: new Date().toISOString()
};
```

#### Destructuring
```javascript
// Array destructuring:
const [first, second] = [10, 20];

// Object destructuring:
const { title, priority, category } = req.body;
// equivalent to:
const title    = req.body.title;
const priority = req.body.priority;
const category = req.body.category;

// With named import:
const { v4: uuidv4 } = require('uuid');
// imports 'v4' from uuid but names it 'uuidv4'
```

#### Fetch API (Frontend → Backend calls)
```javascript
// GET request:
const res  = await fetch('/api/tasks');
const data = await res.json();

// POST request:
const res = await fetch('/api/tasks', {
  method:  'POST',
  headers: { 'Content-Type': 'application/json' },
  body:    JSON.stringify({ title: 'New Task', priority: 'high' })
});

// PATCH request:
const res = await fetch(`/api/tasks/${id}`, {
  method:  'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body:    JSON.stringify({ status: 'completed' })
});

// DELETE request:
const res = await fetch(`/api/tasks/${id}`, { method: 'DELETE' });
```

## ❓ VIVA QUESTIONS + ANSWERS

**Q1: What is a REST API? What does REST stand for?**
REST = Representational State Transfer. It's an architectural style (not a protocol) for designing web APIs. Key principles:
- **Stateless** — each request is independent; server doesn't remember previous requests
- **Client-Server** — frontend and backend are separate
- **Uniform Interface** — uses standard HTTP methods (GET, POST, PUT, PATCH, DELETE)
- **Resources** — everything is a resource (task, user, product) accessed via URLs
- **JSON** — common data format for request/response

**Q2: What is the difference between GET, POST, PATCH, and DELETE?**
| Method | Purpose | Has Body? | Idempotent? |
|--------|---------|-----------|------------|
| GET    | Retrieve data | No | Yes (same result each time) |
| POST   | Create new resource | Yes | No (creates new each time) |
| PATCH  | Partially update resource | Yes | Yes |
| PUT    | Fully replace resource | Yes | Yes |
| DELETE | Remove resource | Usually No | Yes |

Idempotent = calling the same request multiple times gives the same result.

**Q3: What is Express.js? Why use it?**
Express.js is a minimal Node.js web framework. Without Express, building routes requires manual URL parsing and method checking using raw `http` module — very verbose. Express provides:
- Clean routing: `app.get('/path', handler)`
- Middleware support: `app.use(fn)`
- Static file serving: `app.use(express.static('public'))`
- Request body parsing: `app.use(express.json())`
- Error handling

**Q4: What is middleware? Give examples from your project.**
Middleware = function that runs in the request-response pipeline. Has `(req, res, next)` parameters. Must call `next()` to pass control.

In our project:
1. `cors()` — adds headers: `Access-Control-Allow-Origin: *`
2. `express.json()` — parses `{"title":"..."}` body → populates `req.body`
3. `express.static('public')` — serves `index.html` directly
4. Custom logger — logs `[10:30:45] GET /api/tasks`

**Q5: What is the difference between req.params, req.query, req.body?**
```javascript
// URL: PATCH /api/tasks/abc-123?debug=true   (with body: {"status":"completed"})

req.params.id      // "abc-123" — from :id in route definition
req.query.debug    // "true"    — from ?debug=true in URL
req.body.status    // "completed" — from JSON request body (needs express.json())
```

**Q6: What is CORS? Why is it needed?**
CORS = Cross-Origin Resource Sharing. Browser security policy (Same-Origin Policy) blocks JavaScript from making requests to a **different origin** (different domain/port).

Our frontend at `http://localhost:3000` calls `http://localhost:3000/api` — same origin so no issue. But if frontend was at `http://localhost:5500`, it would be blocked without CORS.

The `cors()` middleware adds HTTP headers:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, PATCH, DELETE
```

**Q7: What is UUID? Why use it instead of 1, 2, 3 IDs?**
UUID = Universally Unique Identifier. A randomly generated 128-bit ID: `"a1b2c3d4-e5f6-7890-abcd-ef1234567890"`.

Benefits over sequential IDs (1, 2, 3):
- Can generate IDs on the client without checking the server
- Predictable sequential IDs expose information (users can guess: /api/tasks/1, /api/tasks/2)
- Safe to merge data from multiple sources without ID conflicts
- In production with multiple servers, no coordination needed for ID generation

**Q8: What is PATCH vs PUT?**
Both update a resource. Difference:
- **PUT** — replaces the ENTIRE resource with what you send. Fields not included are removed.
- **PATCH** — partial update. Only changes the fields you send. Other fields remain unchanged.

In our project: we use PATCH to only update `status` without touching `title`, `priority`, etc.

**Q9: How does the in-memory storage work? What are its limitations?**
Tasks are stored in a JavaScript array variable:
```javascript
let tasks = [ {id, title, status, ...}, ... ];
```
When server starts: array populated with sample data.
When you add/update/delete: array modified in RAM.

**Limitations:**
- Data lost when server stops (no persistence)
- Can't scale to multiple servers (each server has its own copy)
- Not suitable for production

**Production solution:** Use a database (MongoDB with mongoose, MySQL with mysql2).

**Q10: What is the difference between Array.find() and Array.findIndex()?**
```javascript
const task  = tasks.find(t => t.id === 'abc');
// Returns the TASK OBJECT itself, or undefined if not found
// Used when: you need the task data

const index = tasks.findIndex(t => t.id === 'abc');
// Returns the INDEX (position number: 0, 1, 2...) or -1 if not found
// Used when: you need to modify tasks[index] or tasks.splice(index, 1)
```

**Q11: Why use `res.status(404).json(...)` instead of just `res.json(...)`?**
HTTP status codes communicate the outcome to the client:
- Without status code: browser/Postman assumes 200 OK even for errors
- With status code: client knows exactly what happened

Best practice: always set appropriate status codes:
```javascript
res.status(201).json({ success: true, task: newTask }); // POST success
res.status(400).json({ success: false, message: 'Invalid data' }); // validation error
res.status(404).json({ success: false, message: 'Not found' }); // missing resource
```

**Q12: What is `Array.splice()` and how does it delete a task?**
`array.splice(startIndex, deleteCount)` removes elements from an array IN PLACE:
```javascript
const arr = ['a', 'b', 'c', 'd'];
arr.splice(1, 1); // remove 1 element starting at index 1
// arr is now ['a', 'c', 'd']
```
In our project:
```javascript
const index = tasks.findIndex(t => t.id === id); // find position: e.g. 2
tasks.splice(index, 1);  // remove 1 element at position 2
```
After splice: that task is gone from the `tasks` array.

**Q13: Explain POSTMAN usage for testing REST APIs.**
POSTMAN is an API testing tool. Steps for testing our API:
1. Open POSTMAN → click "New Request"
2. **GET** → enter URL → click Send → see JSON response in bottom panel
3. **POST** → Method: POST → URL → Body tab → raw → JSON → paste body → Send
4. **PATCH** → Method: PATCH → add status in body → Send
5. **DELETE** → Method: DELETE → URL with ID → Send

Key features:
- No need to write any frontend code to test the API
- Can save requests in Collections
- Can set environment variables (e.g. `{{base_url}}` = `http://localhost:3000`)
- Shows response status code, time, headers, body

**Q14: What is the spread operator (`...`) and how did you use it?**
The spread operator expands an array or object:
```javascript
// Array spread — copy without mutating original:
let filtered = [...tasks];        // creates new copy of tasks array

// Object spread — merge objects:
tasks[index] = {
  ...tasks[index],                // copy all existing task fields
  status: 'completed',            // override status
  updatedAt: new Date().toISOString() // add/update updatedAt
};
// Result: task with all original fields + new status + new updatedAt
```

**Q15: What is the difference between npm start and npm run dev?**
```json
"scripts": {
  "start": "node server.js",      // npm start
  "dev":   "nodemon server.js"    // npm run dev
}
```
- `npm start` → runs with regular `node`. Server must be manually restarted after changes.
- `npm run dev` → runs with `nodemon`. Automatically restarts when you save any `.js` file. Only for development.

**Q16: What happens if you call `next()` but no route matches in Express?**
Express falls through all routes top-to-bottom. If no route matches:
- Without a catch-all: Express sends default `Cannot GET /url` response
- With our 404 handler: `app.use('/api/*', handler)` catches all unmatched API routes

Our global error handler (`app.use((err, req, res, next)=>...)`) catches errors thrown by `next(err)`.
