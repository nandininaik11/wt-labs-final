### UNIT VI — Node.js (Primary Unit)

#### What is Node.js?
Node.js is a **JavaScript runtime** built on Chrome's V8 engine. Normally JS runs only in browsers. Node.js lets you run JavaScript on the **server side** (backend).

Key characteristics:
- **Single-threaded** — one thread handles all requests
- **Non-blocking / Asynchronous** — doesn't wait for DB/file operations to finish; moves on and comes back when ready
- **Event-driven** — uses an Event Loop to handle many concurrent requests
- **NPM (Node Package Manager)** — installs thousands of reusable packages

#### Node.js Modules
```javascript
// Built-in module (no install needed)
const path = require('path');
const fs   = require('fs');

// NPM module (must npm install first)
const express = require('express');

// Your own module (relative path)
const db = require('./db');

// module.exports — what a file exposes to others
module.exports = pool;
```

#### Express.js
Express is a **minimal web framework** for Node.js. It simplifies:
- Creating routes (URL handlers)
- Handling HTTP methods (GET, POST, PUT, DELETE)
- Serving static files
- Middleware chaining

```javascript
const app = express();
app.get('/api/books', handler);     // Route
app.use(express.json());            // Middleware
app.listen(3000, callback);         // Start server
```

#### Middleware
Functions that run between receiving a request and sending a response:
```
Request → [cors()] → [express.json()] → [Route Handler] → Response
```
Each middleware calls `next()` to pass to the next one.

#### REST API (REpresentational State Transfer)
REST uses HTTP methods to perform CRUD operations:
| HTTP Method | CRUD Operation | Our Route |
|-------------|---------------|-----------|
| GET         | Read          | /api/books |
| POST        | Create        | /api/books |
| PUT         | Update        | /api/books/:id |
| DELETE      | Delete        | /api/books/:id |

#### Database Connectivity (mysql2)
```javascript
const pool = mysql.createPool({ host, user, password, database });
const [rows] = await pool.execute('SELECT * FROM books WHERE id = ?', [id]);
// [rows] destructuring: execute returns [rows, fields] — we want rows
// ? placeholder = prepared statement (prevents SQL injection)
```

#### async/await
```javascript
// async function can use await inside it
async function getBooks() {
    const [rows] = await db.execute('SELECT * FROM books');
    // await pauses here until DB responds, then continues
    return rows;
}
// Without async/await (older callback style):
db.execute('SELECT * FROM books', function(err, rows) { ... });
```

#### Connection Pool vs Single Connection
- **Single connection:** Opens → queries → closes. Slow for many requests.
- **Connection Pool:** Keeps 10 connections open and reuses them. Fast and efficient.

### UNIT II — JavaScript / DOM

#### Fetch API (AJAX in modern JS)
```javascript
// GET request
const response = await fetch('http://localhost:3000/api/books');
const data = await response.json(); // parse JSON response

// POST request
const response = await fetch('/api/books', {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify({ title: 'Book', author: 'Author', year: 2024 })
});
```
Fetch replaces older XMLHttpRequest (XHR) and is Promise-based.

```javascript
// getElementById() — get one element by id attribute

document.querySelectorAll('.section').forEach(s => s.classList.remove('active'));

// forEach() — iterate over NodeList
// classList.remove/add — toggle CSS classes

element.textContent = 'New text'; // safe (escapes HTML)
element.innerHTML   = '<b>HTML</b>'; // renders HTML
```

```javascript
form.addEventListener('submit', function(event) {
    event.preventDefault(); // stop browser default submit
```

## ❓ VIVA QUESTIONS + ANSWERS

**Q1: What is Node.js? How is it different from PHP?**
Node.js is a server-side JavaScript runtime. PHP is a dedicated server-side language.
Differences:
| Node.js | PHP |
|---------|-----|
| JavaScript everywhere (frontend + backend) | PHP only on server |
| Asynchronous, non-blocking by default | Synchronous by default |
| npm ecosystem (1.8M packages) | Composer ecosystem |
| Best for real-time apps, APIs | Best for traditional web pages |
| Runs via `node server.js` | Runs via Apache/Nginx + PHP-FPM |

**Q2: What is NPM? What does `npm install` do?**
NPM = Node Package Manager. It's the default package manager for Node.js. `npm install` reads `package.json`, downloads all listed dependencies from https://registry.npmjs.org/ into a `node_modules/` folder. `package-lock.json` is auto-generated to lock exact package versions for reproducibility.

**Q3: What is Express.js? Why do we use it instead of raw Node.js?**
Express.js is a lightweight web framework for Node.js. Without Express, creating a web server requires handling raw HTTP:
```javascript
// Raw Node.js (hard):
const http = require('http');
http.createServer((req, res) => {
    if (req.url === '/api/books' && req.method === 'GET') { ... }
}).listen(3000);

// With Express (easy):
app.get('/api/books', (req, res) => { ... });
```
Express provides: routing, middleware, static file serving, request parsing.

**Q4: Explain Middleware in Express.**
Middleware is a function with `(req, res, next)` parameters. It runs between request receipt and response sending. Types used:
- `cors()` — adds CORS headers so browser can call API from a different origin
- `express.json()` — parses `Content-Type: application/json` request bodies into `req.body`
- `express.static('public')` — serves files from /public folder directly
- Custom middleware: `(req, res, next) => { console.log(req.url); next(); }`

**Q5: What is REST API? What HTTP methods did you use?**
REST (Representational State Transfer) is an architectural style for web APIs. It uses HTTP methods to express intent:
- **GET** — retrieve data (no side effects; safe to call multiple times)
- **POST** — create new resource (sends data in request body)
- **PUT/PATCH** — update existing resource
- **DELETE** — remove a resource
Response uses HTTP status codes: 200 OK, 201 Created, 400 Bad Request, 404 Not Found, 500 Server Error.

**Q6: What is async/await? What is a Promise?**
A **Promise** is a JavaScript object representing a future value (will be resolved or rejected). `async/await` is syntactic sugar over Promises:
```javascript
// Promise-style (harder to read):
db.execute('SELECT * FROM books')
  .then(([rows]) => res.json(rows))
  .catch(err => res.status(500).json({error: err.message}));

// async/await style (reads like synchronous code):
async function handler(req, res) {
    try {
        const [rows] = await db.execute('SELECT * FROM books');
        res.json(rows);
    } catch (err) {
        res.status(500).json({ error: err.message });
    }
}
```
`await` pauses the function until the Promise resolves, but does NOT block other requests (still non-blocking).

**Q7: What is the Fetch API? How is it different from XMLHttpRequest?**
Fetch API is a modern browser API for making HTTP requests. It's Promise-based (cleaner than callbacks). XMLHttpRequest (XHR) is the older approach:
```javascript
// Old XHR way:
const xhr = new XMLHttpRequest();
xhr.open('GET', '/api/books');
xhr.onload = function() { const data = JSON.parse(xhr.responseText); };
xhr.send();

// Modern Fetch way:
const response = await fetch('/api/books');
const data = await response.json();
```
Fetch is simpler, chainable, and returns Promises.

**Q8: What is CORS? Why did you use it?**
CORS = Cross-Origin Resource Sharing. Browsers block requests from one origin (http://localhost:3000) to a different origin (http://api.example.com) by default — this is the Same-Origin Policy. The `cors()` middleware adds HTTP headers:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
```
Without this, the browser would block the frontend from calling the API if they're on different ports or domains.

**Q9: What is a Connection Pool? Why not just use one connection?**
A connection pool maintains multiple DB connections open and ready. When a request comes in, it borrows a connection from the pool, uses it, and returns it. Benefits:
- **Performance:** No overhead of opening a new connection per request (connecting takes time)
- **Concurrency:** Multiple requests can use different connections simultaneously
- **Limits:** `connectionLimit: 10` prevents overwhelming the DB server

**Q10: What is the difference between `req.params`, `req.query`, and `req.body`?**
```javascript
// URL: /api/books/5?search=gatsby (with POST body: {"title": "Book"})

req.params.id     // "5"    — from URL path segment :id
req.query.search  // "gatsby" — from ?search=gatsby in URL
req.body.title    // "Book" — from JSON request body (POST/PUT)
```

**Q11: What is SQL Injection? How does your code prevent it?**
SQL Injection: attacker puts SQL code into input, e.g. entering `'; DROP TABLE books; --` as a title. Without protection: `"SELECT * WHERE title = '" + title + "'"` — this would execute the injected SQL!

Prevention via **prepared statements**:
```javascript
await db.execute('SELECT * FROM books WHERE book_id = ?', [bookId]);
// ? is a placeholder — mysql2 escapes the value before inserting into SQL
// The value is NEVER concatenated as text into the SQL string
```

**Q12: What is `module.exports` in Node.js?**
Node.js uses the **CommonJS module system**. Each file is its own module with private scope. `module.exports` defines what other files can access when they `require()` this file:
```javascript
// db.js
const pool = mysql.createPool({...});
module.exports = pool;         // export the pool object

// server.js
const db = require('./db');    // import — db is now the pool
db.execute('SELECT ...');      // use it
```

**Q13: Explain the package.json file.**
`package.json` is the project manifest file:
```json
{
  "name": "library-app",          // project name
  "version": "1.0.0",
  "main": "server.js",            // entry point
  "scripts": {
    "start": "node server.js",    // npm start
    "dev":   "nodemon server.js"  // npm run dev
  },
  "dependencies": {               // needed in production
    "express": "^4.18.2",
    "mysql2":  "^3.6.0",
    "cors":    "^2.8.5"
  },
  "devDependencies": {            // only needed during development
    "nodemon": "^3.0.1"
  }
}
```

**Q14: What is Nodemon? Why is it useful?**
Nodemon is a development tool that watches your project files and automatically restarts the Node.js server when any file changes. Without nodemon, you'd have to manually stop (Ctrl+C) and restart (`node server.js`) after every code change. Usage: `npm run dev` or `npx nodemon server.js`.

**Q15: What is the Event Loop in Node.js?**
Node.js is single-threaded but handles many requests concurrently through the Event Loop:
1. Request 1 arrives → starts DB query → puts callback in queue
2. Request 2 arrives → starts DB query → puts callback in queue (without waiting for Request 1)
3. DB responds for Request 1 → Event Loop picks up callback → sends response
4. DB responds for Request 2 → Event Loop picks up callback → sends response

This is "non-blocking I/O" — the thread never waits; it always handles the next available task.
