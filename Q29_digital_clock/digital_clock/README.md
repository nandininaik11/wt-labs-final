## 📖 THEORY — WT Syllabus Unit V: React

---

### What is React?
React is a JavaScript **library** for building user interfaces. Created by Facebook (Meta). Key ideas:
- **Component-based:** UI is split into small, reusable pieces (components)
- **Declarative:** You describe WHAT the UI should look like, React handles HOW to update it
- **Virtual DOM:** React keeps a virtual copy of the DOM in memory, diffs it, and only updates changed parts (fast!)
- **One-way data flow:** Data flows from parent → child via props

---

### Functional Component
A React component is a JavaScript function that returns JSX:
```jsx
function Clock() {
    return (
        <div className="clock">
            <h1>12:30:45</h1>
        </div>
    );
}
export default Clock;
```
No `class` or `this` needed — just a regular function.

---

### JSX (JavaScript XML)
JSX looks like HTML but is actually JavaScript. Babel compiles it to:
```jsx
// JSX (what you write):
const element = <h1 className="title">Hello</h1>;

// What Babel compiles it to:
const element = React.createElement('h1', { className: 'title' }, 'Hello');
```
JSX rules:
- `class` → `className`
- `for` → `htmlFor`
- Self-close empty tags: `<br />` `<input />`
- JS expressions in `{ }`: `<p>{2 + 2}</p>` → renders "4"
- Event handlers camelCase: `onClick`, `onChange`, `onSubmit`

---

### useState Hook — Task 2
```jsx
const [time, setTime] = useState(new Date());
//     ^^^^  ^^^^^^^   ^^^^^^^^ ^^^^^^^^^^^^^
//     state setter    hook     initial value
```
- Returns `[currentValue, setterFunction]`
- When `setTime(newValue)` is called → React **re-renders** the component
- State is preserved between re-renders (unlike regular variables)

```jsx
// State updates trigger re-renders:
const [count, setCount] = useState(0);
<button onClick={() => setCount(count + 1)}>Click</button>
// Each click: setCount called → React re-renders → count displays new value
```

---

### useEffect Hook — Task 3
```jsx
useEffect(() => {
    // This runs AFTER render
    const id = setInterval(() => {
        setTime(new Date()); // update state every second
    }, 1000);

    // Cleanup function — runs before next effect or unmount
    return () => clearInterval(id);

}, [isRunning]); // dependency: re-run when isRunning changes
```

#### Dependency Array behavior:
```jsx
useEffect(fn);           // runs after EVERY render
useEffect(fn, []);       // runs ONCE after first render (mount)
useEffect(fn, [a, b]);   // runs when a or b changes
```

#### Component Lifecycle mapped to Hooks:
| Class Component Lifecycle | Hook Equivalent |
|--------------------------|-----------------|
| `componentDidMount`      | `useEffect(() => {...}, [])` |
| `componentDidUpdate`     | `useEffect(() => {...}, [dep])` |
| `componentWillUnmount`   | `useEffect(() => { return cleanup; }, [])` |

---

### Props — Passing Data Between Components
```jsx
// Parent passes props:
<TimeDisplay hh="12" mm="30" ss="45" isRunning={true} />

// Child receives props:
function TimeDisplay({ hh, mm, ss, isRunning }) {
    return <div>{hh}:{mm}:{ss}</div>;
}
```
Props are **read-only** — child cannot modify them. They flow one-way: Parent → Child.

---

### State Lifting (Pass data child → parent)
Child cannot directly change parent state. Solution: parent passes a callback function as prop:
```jsx
// Parent:
function Clock() {
    const [isRunning, setIsRunning] = useState(true);
    const handleToggle = () => setIsRunning(prev => !prev);

    return <Controls onToggle={handleToggle} />;
    //                ^^^^^^^^ pass function as prop
}

// Child:
function Controls({ onToggle }) {
    return <button onClick={onToggle}>Toggle</button>;
    //                      ^^^^^^^^ child calls parent's function
}
```

---

### Component Composition
Components compose (contain) other components — forming a tree:
```
App
└── Clock
    ├── TimeDisplay
    ├── Controls
    └── InfoPanel
```

---

### Conditional Rendering
```jsx
// Ternary operator:
{isRunning ? <span>Running</span> : <span>Stopped</span>}

// Short-circuit (&&):
{showSeconds && <SecondsDisplay seconds={ss} />}

// Null = renders nothing:
{condition ? <Element /> : null}
```

---

### List Rendering (key prop)
```jsx
const themes = ['blue', 'green', 'purple'];

themes.map(theme => (
    <button key={theme}>{theme}</button>
    //      ^^^^^^^^^^ REQUIRED: unique identifier for each list item
    // Without key: React warns and may have rendering bugs
))
```

---

### useCallback Hook
```jsx
const handleToggle = useCallback(() => {
    setIsRunning(prev => !prev);
}, []); // [] = never recreate this function
```
Memoizes a function so it's not recreated on every render. Important when passing functions as props to child components (avoids unnecessary re-renders).

---

### React Rendering Process
1. State/props change
2. React calls the function component again
3. JSX is returned (describes new UI)
4. React compares with Virtual DOM (diffing)
5. Only the changed parts update in the real DOM

## ❓ VIVA QUESTIONS + ANSWERS

**Q1: What is React? Why use it instead of plain JavaScript?**
React is a JavaScript library for building UIs. Advantages over plain JS:
- **Components:** Reusable, self-contained UI pieces
- **Virtual DOM:** Only updates changed parts → faster than re-rendering entire page
- **Declarative:** Describe the desired UI, React handles DOM updates
- **State management:** useState automatically re-renders on data change
- **Ecosystem:** Huge community, tools like React Router, Redux

**Q2: What is the difference between a functional component and class component?**
| Functional | Class |
|-----------|-------|
| Plain JS function | ES6 class extending React.Component |
| Uses Hooks (useState, useEffect) | Uses lifecycle methods (componentDidMount etc.) |
| No `this` keyword | Uses `this.state`, `this.setState` |
| Simpler, modern (recommended) | Older style |
```jsx
// Functional (modern):
function Clock() {
    const [time, setTime] = useState(new Date());
    return <div>{time.toString()}</div>;
}

// Class (old):
class Clock extends React.Component {
    constructor(props) { super(props); this.state = { time: new Date() }; }
    render() { return <div>{this.state.time.toString()}</div>; }
}
```

**Q3: Explain useState(). What happens when setState is called?**
`useState(initialValue)` is a Hook that adds state to a functional component. Returns `[state, setter]`. When `setter(newValue)` is called:
1. React schedules a re-render
2. The component function runs again
3. `useState` returns the new value
4. JSX is re-evaluated and React updates only changed DOM nodes

**Q4: Explain useEffect(). What is the cleanup function?**
`useEffect(fn, deps)` runs side effects after rendering. In our clock:
```jsx
useEffect(() => {
    const id = setInterval(() => setTime(new Date()), 1000);
    return () => clearInterval(id); // CLEANUP
}, [isRunning]);
```
The returned cleanup function:
- Runs before the effect runs again (when `isRunning` changes)
- Runs when the component unmounts (removed from DOM)
- Without it: old intervals would keep running after pause → memory leak

**Q5: What is JSX? Is it HTML?**
JSX is a syntax extension for JavaScript. It looks like HTML but is NOT HTML. It gets compiled by Babel to `React.createElement()` calls:
```jsx
// JSX:
<button className="btn" onClick={handleClick}>Start</button>

// Compiled to:
React.createElement('button', { className: 'btn', onClick: handleClick }, 'Start')
```
Differences from HTML: `className` not `class`, `htmlFor` not `for`, all tags must close, JS in `{}`.

**Q6: What are Props? How do they differ from State?**
| Props | State |
|-------|-------|
| Passed from parent to child | Managed within the component |
| Read-only (immutable) | Can be updated with setter |
| `function Child({ name }) {}` | `const [name, setName] = useState('')` |
| Data flows DOWN | Updates cause re-render |

**Q7: What is the key prop? Why is it required in lists?**
`key` is a special React prop that uniquely identifies list items. React uses it to efficiently update the DOM when lists change:
```jsx
themes.map(t => <Button key={t.id} ... />)
```
Without `key`: React can't tell which items changed/added/removed → potential rendering bugs and performance issues. Keys must be unique among siblings; don't use array index as key if list order can change.

**Q8: What is the Virtual DOM? How does it work?**
Virtual DOM is a lightweight JavaScript object copy of the real DOM kept in memory:
1. When state changes, React creates a NEW Virtual DOM
2. React **diffs** new vs old Virtual DOM (finds differences)
3. React updates ONLY the changed parts in the real DOM (reconciliation)

This is faster than: `document.getElementById('time').innerHTML = newTime` on every update because DOM operations are expensive.

**Q9: Explain the component lifecycle in terms of Hooks.**
```
MOUNT (component added to DOM):
  → Component function runs
  → JSX rendered
  → useEffect(fn, []) runs once

UPDATE (state/props change):
  → Component function runs again
  → Cleanup of previous effect runs
  → New effect runs

UNMOUNT (component removed from DOM):
  → Cleanup function from useEffect runs
  → clearInterval called → timer stops
```

**Q10: What is state lifting? Show an example from your project.**
State lifting = moving state to a common parent when multiple children need to share it. In our clock:
```jsx
// Clock (parent) owns isRunning state:
const [isRunning, setIsRunning] = useState(true);

// Passes setter as callback to Controls (child):
<Controls onToggle={() => setIsRunning(prev => !prev)} />

// Controls calls it on button click:
<button onClick={onToggle}>Pause</button>
// Child → calls parent's function → updates parent's state → re-renders both
```

**Q11: Why did you use `setTime(new Date())` inside setInterval instead of just using the current time?**
Inside a `setInterval` callback, the variables from the outer scope are captured in a **closure** at the time the interval was created. If we just did `setTime(time)` where `time` is from useState, it would always use the **stale** initial value (closure captures the value, not a reference to the latest state).

Using `new Date()` directly creates a fresh Date object at the time the callback runs, so it always gets the actual current time regardless of closure issues.

**Q12: What is useCallback? Why did you use it?**
`useCallback(fn, deps)` returns a memoized (cached) function that only changes when dependencies change:
```jsx
const handleToggle = useCallback(() => {
    setIsRunning(prev => !prev);
}, []); // empty deps → never recreated
```
Without `useCallback`: every time Clock re-renders, a new `handleToggle` function is created → passed as new prop to Controls → Controls re-renders unnecessarily. With `useCallback`: same function reference is reused.

**Q13: What is the difference between `onClick={handleToggle}` and `onClick={handleToggle()}`?**
```jsx
onClick={handleToggle}   // ✅ CORRECT: pass function REFERENCE
                         // Called when button is clicked

onClick={handleToggle()} // ❌ WRONG: calls function IMMEDIATELY during render
                         // Returns undefined (or whatever handleToggle returns)
                         // Not called on click, called on render!

// When you need to pass arguments, use arrow function:
onClick={() => onThemeChange(t.id)} // ✅ Arrow function creates new function
                                     // that calls onThemeChange(t.id) when clicked
```

**Q14: What is `padStart()`? Why use it for the clock?**
`String.padStart(targetLength, padString)` pads the start of a string to reach the target length:
```javascript
'9'.padStart(2, '0')   // → '09'
'12'.padStart(2, '0')  // → '12' (already 2 chars, no padding)
```
Used because `getHours()` returns `9` (one digit) but we want `09` (two digits) for proper HH:MM:SS format. Without it: 9:5:3 instead of 09:05:03.

**Q15: What is a Single Page Application (SPA)? Is React an SPA?**
SPA = web app that loads ONE HTML page and dynamically updates the content using JavaScript — no full page reloads. React apps are typically SPAs:
- `public/index.html` is the only HTML file
- React Router (optional) handles navigation by updating the URL and rendering components
- All page transitions happen in JavaScript — no server round-trips
- Benefits: faster navigation, better UX, app-like feel
- Drawback: initial load takes longer, SEO harder (though Next.js solves this)
